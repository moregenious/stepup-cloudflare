# Step Up English — CRM/LMS

CRM и LMS языковой школы Step Up English. Владелец и разработчик — Никита Ли (преподаватель английского, совладелец школы). Пользователи: админ, преподаватели, ученики (и их родители смотрят кабинет ученика).
Прод: https://stepup-english.stepup-english.workers.dev · Репозиторий: github.com/moregenious/stepup-cloudflare

## Как работать с Никитой
- Общаемся по-русски.
- «Ничего не меняй» / «пока ничего не меняй, ответь на вопрос» → только ответ, никаких правок файлов.
- «Покажи варианты» / «объясни, как ты это видишь перед изменениями» → сначала варианты или план, правки только после выбора.
- Деплой и коммиты делает он сам: `npm test` → `npx wrangler deploy` → коммит и push в GitHub Desktop. Не деплой и не пушь без прямой просьбы.
- Проверяет результат скриншотами с телефона и ноутбука; мобильная вёрстка важна (320–390 px).

## Команды
- `npm run dev` — локальный сервер http://localhost:8787 (dev/server.mjs, поддельные D1/R2 из dev/fake-*.mjs, данные в `data/`).
- `npm test` — node --test tests/*.test.mjs (api.test.mjs, gameStreak.test.mjs). Должны проходить перед каждым деплоем.
- `npx wrangler deploy` — публикация.
- Перезапуск dev-сервера после правок серверного кода (src/, public/js/shared/) обязателен — иначе тестируется старый код.

## Архитектура
- Cloudflare Workers + D1 + R2, бесплатный тариф: 10 мс CPU на запрос, 100k запросов/день, D1 — 5M чтений и 100k записей строк в день, 500 МБ; одна строка D1 не больше 2 МБ.
- `src/worker.js` — роутинг; `src/api/*` — эндпоинты (auth, state, files, events, admin, push, config).
- **Хранилище — документы, разбитые на шарды** (`src/lib/shards.js`): коллекции LIST_COLLS / MAP_COLLS, MAX_SHARD_BYTES = 950 КБ. pointRecords — 8 шардов (~23k записей; при текущем темпе заполнится примерно за 3 месяца → нужен архив истории баллов, ещё не сделан). MAP: `payments`, `attendance`.
- **Оптимистичные транзакции** с якорным meta-документом (`src/lib/engine.js`). Сервер сам считает баллы мини-игр, заморозки серии, покупки.
- **Права по ролям** — `src/lib/rules.js` (санитизация: ученик видит только своё; passThrough для части коллекций).
- **Клиент**: `public/js/store.js` (вся бизнес-логика, ~4.7k строк), `public/js/sync.js` (SyncEngine: diff/rebase, опрос, очередь отправки с таймаутами и backoff, `flush()` перед выходом/сменой аккаунта), `public/js/api.js`.
- **Общий модуль** `public/js/shared/gameStreak.js` импортируют и Worker, и браузер: серия мини-игр, недельный лимит (100 → 500, +10 за каждые 7 дней подряд, −10 за пропущенный день, минимум 10 очков в день), заморозки (150 ⭐, максимум 3). Менять правила — только здесь, и обновлять tests/gameStreak.test.mjs.
- **Аналитика**: отдельная таблица D1 `events` (`src/lib/events.js`), пакетный POST /api/events, CSV-выгрузка для админа с обезличиванием (HMAC-псевдонимы). Клиент — `public/js/analytics.js`.
- **Посещаемость**: коллекция `attendance`, ключ `<groupId|ind-studentId>_<YYYY-MM-DD>`; отсутствующим не начисляются баллы «всем».
- **Разделение по преподавателям (вариант A, только интерфейс)**: ученик принадлежит преподавателю своей группы, иначе `student.teacherId`; без них — виден всем. Админ фильтрует в шапке (localStorage `stepup_admin_teacher_filter`). Рейтинги школы считаются по всем (`{allTeachers:true}`). Серверной изоляции (вариант B) пока нет.
- Учебные планы: домашка — если на уроке поле пустое, берётся с ближайшего предыдущего урока (`getEffectiveHomeworkForLesson`).

## Данные и безопасность
- Секреты: `SESSION_SECRET` через `wrangler secret`; локально `.dev.vars` (в .gitignore). Не писать пароли и ключи в код, README и этот файл.
- `data/`, бэкапы `*backup*.json`, выгрузки — содержат персональные данные учеников, не коммитить.
- Для портфолио и публичного GitHub — только обезличенная выгрузка («Обезличить»). Личные планы Никиты (career-cases.md) в репозиторий не класть.
