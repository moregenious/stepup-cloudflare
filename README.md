# Step Up English — CRM & LMS for an English language school

> **EN:** A production web app used by a real language school: students, groups, teachers, weekly schedule,
> lesson plans with audio and Word materials, vocabulary trainer, gamification (points, shop, mini-games),
> payments and attendance. Vanilla JS single-page app + serverless backend on **Cloudflare Workers**,
> **D1 (SQLite)** and **R2**, running entirely on the free tier. Role-based access, server-side
> validation, offline-friendly delta sync.

Веб-приложение, которым пользуется действующая школа английского языка: около 90 учеников, преподаватели
и администратор работают в нём каждый день с компьютеров и телефонов.

## Возможности

| Роль | Что доступно |
|---|---|
| **Администратор** | дашборд, группы, ученики (в т. ч. импорт из Word), преподаватели, недельное расписание с каникулами, планы уроков по учебникам (10 месяцев × 8 уроков) с аудио и документами, словарь, оплаты, посещаемость, баллы, магазин, журнал действий, резервные копии |
| **Преподаватель** | кабинет с группами и уроками на сегодня, «кабинет класса» для урока, отметка посещаемости, начисление баллов, загрузка материалов и слов из Word |
| **Ученик** | личный кабинет, домашние задания с аудиоплеером (замедление 0.5×–1.25×), персональный словарь, неправильные глаголы, 9 мини-игр по грамматике и лексике, магазин наград за баллы, анкета |

Вход: сотрудники — логин или телефон и пароль; ученики — телефон и 4-значный PIN или QR-код из памятки.

## Архитектура

```
Браузер (Vanilla JS SPA, ES-модули, без сборки)
   │  статические файлы  ── Cloudflare Static Assets (бесплатно, без лимита запросов)
   │  /api/*  /files/*
   ▼
Cloudflare Worker (src/worker.js)
   ├── auth    вход, подписанные HttpOnly-сессии (HMAC-SHA256), PBKDF2-хеши паролей, защита от перебора
   ├── state   выдача данных с учётом роли (ученик не видит телефоны и PIN одноклассников)
   ├── push    приём изменений: проверка прав, транзакционная запись, серверный учёт баллов
   ├── files   загрузка и отдача файлов (HTTP Range для перемотки аудио), только для вошедших
   └── admin   резервное копирование и восстановление
        │
        ├── D1 (SQLite)  данные школы
        └── R2           аудио, документы, фото
```

### Ключевые решения

- **Шардирование под бесплатные лимиты.** Сущности (ученики, баллы, уроки…) хранятся не построчно, а
  в ~45 документах-шардах внутри D1, у каждой строки есть номер ревизии. Полная загрузка — около 25 чтений,
  проверка изменений — одно чтение, клиент скачивает только изменившиеся строки.
- **Дельта-синхронизация с перебазированием.** Клиент работает с привычным объектом состояния, а модуль
  `public/js/sync.js` вычисляет построчный и пополевой diff с последней серверной копией, отправляет только
  изменения и накладывает несохранённые локальные правки поверх свежих данных. Одновременные правки разных
  полей с разных устройств не затирают друг друга.
- **Оптимистичные транзакции поверх D1.** У D1 нет интерактивных транзакций, поэтому запись идёт пакетом
  (`batch`), который выполняется, только если версия «якорного» документа не изменилась; при конфликте —
  повтор (`src/lib/storage/d1.js`).
- **Сервер — источник истины.** Баланс баллов считает сервер (леджер), ученик может начислить себе баллы
  только по жёстким правилам (анкета — один раз, день рождения — раз в год, мини-игры — недельный лимит),
  покупки проверяются по балансу и цене товара.
- **Экономия CPU (лимит 10 мс на запрос).** Шарды, не требующие фильтрации по роли, отдаются как сырой JSON
  без разбора; пароли — PBKDF2 через WebCrypto с подобранным числом итераций.

## Технологии

- **Frontend:** HTML, CSS, JavaScript (ES-модули, без фреймворков и сборщиков), JSZip для разбора .docx в браузере
- **Backend:** Cloudflare Workers (JavaScript, Web API: `fetch`, `crypto.subtle`)
- **Хранилища:** Cloudflare D1 (SQLite), Cloudflare R2 (объектное хранилище)
- **Инструменты:** Wrangler, Node.js `node:test`, Playwright (e2e-проверки), GitHub Actions
- Объём: ~23 тыс. строк клиентского JS, ~6 тыс. строк CSS, ~2 тыс. строк серверного кода

## Структура

```
public/            клиентское приложение (index.html, css/, js/)
  js/store.js      бизнес-логика: расписание, уроки, баллы, словарь, магазин
  js/sync.js       дельта-синхронизация с сервером
  js/views/        экраны приложения
src/
  worker.js        маршрутизация Worker
  api/             обработчики API
  lib/             права ролей, движок синхронизации, сессии, работа с D1/R2
migrations/        схема БД
tools/             миграция данных, загрузка файлов, сброс пароля
dev/               локальный запуск: SQLite (node:sqlite) вместо D1, папка вместо R2
tests/             тесты API
```

## Запуск локально

```bash
npm install
npm run dev     # http://localhost:8787 — тот же код Worker, D1 эмулируется через SQLite
npm test
```

Нужен Node.js 22.13+. Развёртывание и перенос данных описаны в [docs/DEPLOY.md](docs/DEPLOY.md).

## История проекта

Первая версия была полностью клиентской: все данные хранились в браузере и целиком перезаписывались в
Firebase Firestore. Это приводило к потере данных при работе с нескольких устройств и открывало пароли всем
посетителям. Во второй версии появился полноценный бэкенд с серверной авторизацией, правами доступа и
синхронизацией изменений, а проект переехал на Cloudflare (Workers + D1 + R2) с переносом всех данных
и ~900 учебных файлов.
